共同的架构哲学与取舍
Host 与 Client 分离

涉及模型可见状态的跑在 Host，纯 UI 逻辑跑在 Client 填槽位。Host 修改重启生效，Client 修改刷新即可。

填槽位，不改造

严格不修改宿主原有界面代码，只向 Harness 预留槽位注册内容，宿主升级绝不悄悄破坏插件功能。

说人话，不甩堆栈

配置不对或网络异常时，通知直接明确指出该去修改哪个设置项，杜绝冷冰冰的 500 或一大段调用栈。

持久化统一于 ~/.dsh/

每个插件独占一个子目录，卸载或升级包不会误删用户数据，重装后自动平滑接上所有历史数据。

安装与启用方式

推荐方式一：DSH 客户端内置安装程序
打开应用内「设置 ➔ 内置插件」，在输入框粘贴对应包名，点击安装后重启应用即可自动注册进 dsh.profile.bundles：

dsh-prompt-crafter

方式二：终端 CLI 命令行安装
完全退出应用后，在桌面 profile 目录下执行 pnpm 安装：

cd ~/.dsh/profiles/desktop && pnpm add dsh-prompt-crafter dsh-visual-card dsh-memory-system-prompt dsh-web-search-router
