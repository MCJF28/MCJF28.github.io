dsh-web-search-router

搜索路由分流中间件：按当前对话所用模型通道，智能分流官方 Messages 协议搜索与自建第三方搜索服务。全面接管搜索链路，在不可用时输出精确可读的人类语言诊断，彻底终结冰冷的 500 崩溃。

查看分流架构 安装与配置
模型通道智能分流示意
通道 A：官方 DeepSeek 账号 使用官方认证鉴权凭据
➔
官方原生搜索工具 Anthropic Messages 协议原生 web_search
通道 B：第三方/自定义模型通道 本地 Ollama / vLLM / 第三方代理 API
➔
自建搜索服务路由 (Parallel 兼容) 连接你配置的自定义 Search Provider
清晰可读的人性化失败归因

搜索失败时右下角弹出精准排错卡片，12 秒自动淡出或手动确认，直接指引修改设置：

!
未配置搜索凭据

还没有可用的搜索服务。请前往「设置 ➔ 搜索」填写有效的 API Key 与服务地址。

!
上游搜索引擎拒绝 (401 / 403)

上游检索服务拒绝了本次请求：Token 已过期或额度耗尽。错误详情已记录。

⏳
网络连接超时 (Timeout)

自建搜索端点响应耗时超过阈值（15s），已安全断开并提示，不阻塞对话主进程。

三级凭据优先级解析

凭据阶梯解析顺序

1. 活跃账号令牌（Account Token）
2. 凭据存储里的 DEEPSEEK_API_KEY
3. 应用启动环境变量
前一个获取成功即生效，否则平滑顺延探测下一级。

破解 Cordis Provider 死锁

如果 base 预置了 searchProvider: deepseek-official，通过在 cordis.patch.yml 中重写覆盖，保证本插件注册的 custom-search 真正被调度。

cordis.patch.yml 覆写规范
# 若第三方通道无法调用，在 profile 的 cordis.patch.yml 中加入：
- id: web
  name: "@deepseek-ai/dsh-web"
  config:
    searchProvider: custom-search
    fetchProvider: http
安装与启用

在 DeepSeek Harness 桌面端打开「设置 ➔ 内置插件」，粘贴包名点击安装并重启：
